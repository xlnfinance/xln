01 / Why

A recovery protocol should outlive its fastest implementation.

BrainVault V1 freezes every byte that matters: normalization, salts, Argon2id parameters, shard ordering, the BLAKE3 fold, mnemonic projection, and wallet paths.

Engines, worker counts, timing, and hardware may change. Given the same semantic inputs, the 32-byte root must not. Frozen vectors make that claim executable rather than aspirational.

What bunx actually does

It does not compile Rust, C, or Metal during installation. On Apple Silicon, BrainVault selects a bundled prebuild and verifies its release-manifest hash before execution. If the binary itself is inside your threat model, use the source-verification path first.

05 / Maximum paranoia

Trust is a sequence,
not a download button.

This is the strongest practical path shipped with BrainVault. A failed step is a stop, not permission to fall back.

  1. 01

    Authenticate and audit the code

    Pin an immutable commit through an independent channel. Begin with the 289-line canonical root surface and frozen vectors.

    SPEC-V1.md · primitives/* · canonical.ts
  2. 02

    Audit dependency integrity

    Review exact versions, registry integrity, licenses, vendored native source, and the complete shipped manifest.

    package.json · bun.lock · MANIFEST.sha256
  3. 03

    Install inertly and go offline

    Populate only an audited cache, disconnect networking, freeze the lock, and disable all lifecycle scripts.

    bun install --offline --frozen-lockfile --ignore-scripts
  4. 04

    Rebuild every native artifact twice

    Clean, locked builds must match each other and every bundled M1/M3 prebuild byte-for-byte after normalized signing.

    bun run verify:source
  5. 05

    Prove vectors, failures, and engine parity

    Run the package suite, 12-way release matrix, native release checks, and cross-engine smoke before real secrets.

    bun run check · bun run test:matrix · bun ./brainvault --smoke
  6. 06

    Recover privately, then independently repeat

    Use a clean offline machine with no recording. Freshly derive again and compare the complete first address before funding.

    No tmux · no camera · no network · no copied seed

Why there is no bun run build

TypeScript runs directly in Bun, and “it compiled” proves almost nothing. verify:source proves the stronger property: two clean native builds reproduce the audited, manifest-covered prebuilds.

07 / Read before funding

There is no
“forgot password.”

  • Eight characters is input hygiene, not safety. Use a strong, unique password you can reproduce exactly.
  • Your first address is public but privacy-sensitive. Sharing it links activity.
  • There is intentionally no recovery receipt. Wrong inputs deterministically create a different wallet.
  • Loss is irreversible. Confirm recovery independently before moving meaningful funds.
  • No terminal can defeat cameras, recording, swap, crash dumps, or SIGKILL. Control the machine and room.
