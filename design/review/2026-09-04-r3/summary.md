## Priority fixes by reviewer

### openrouter/google/gemini-flash-latest · desktop-dark · 819

xln desktop dark establishes an exceptionally strong, authoritative fintech aesthetic with crisp cryptographic cues and elegant bilateral bar concepts. Its primary weakness is desktop canvas utilization, leaving extensive dark dead zones and underpopulated second columns across secondary views.

- Default-select the first transaction in Activity view on desktop so the right-hand receipt pane is never an empty placeholder box.
- Bring the visceral value bilateral bar into the Receipt modal and Activity detail pane to visually corroborate the settlement delta.
- Provide active selection styling (surface fill #1A1F2C + indicator border) to list rows when viewing details side-by-side.
- Rebalance desktop vertical layout across Pay, Swap, and Account pages by adding route stats, execution parameters, or transaction history rather than leaving 60% empty canvas.
- Enclose the Receive QR code in an elegant, padded dark container card with a softly framed off-white QR plate to eliminate harsh unstyled contrast.

### zai-coding-cn/glm-4.6v · desktop-light · 840

The desktop-light variant demonstrates strong visual design with excellent visceral value execution and clear data presentation. The one-scale bar principle is consistently applied across screens, creating an intuitive money visualization system. Typography and layout are generally well-executed, though some screens show inconsistencies in hierarchy and visual noise.

- Standardize typography and remove redundant information across all screens
- Enhance visual hierarchy in left navigation and filter tabs
- Improve QR code and input field visual treatments for better emphasis
- Add clearer visual indicators for interactive elements and active states
- Refine color contrast and semantic consistency in light theme

### openrouter/google/gemini-flash-latest · desktop-light · 788

The light desktop variant has strong typographic foundations and excellent implementation of the bilateral visceral bars on primary cards, but suffers from severe desktop canvas underutilization and inconsistent card structuring across secondary screens. Visual trust is high due to explicit cryptographic state labels, though interactive affordances (copying IDs, row selection, input field containers) feel unfinished.

- Unify two-column desktop grid constraints across all screens to eliminate vast dead space below left-hand content and right-hand sidebars.
- Bring the visceral value scale bar into Receipts and Activity feeds so the 'every horizontal bar is drawn at ONE absolute scale' rule is honored everywhere money is shown.
- Provide active selection styling in master-detail views (Activity detail and list) and formalize input container borders in Pay/Swap/Receive.
- Add micro-affordances for cryptographic trust: one-click copy buttons and hover previews on all truncated hashes and Entity IDs.
- Fix light-theme contrast on secondary metadata (fees, capacity captions, empty lanes) by darkening from muted grey to slate-700 (#374151).

### zai-coding-cn/glm-4.6v · desktop-dark · 865

The desktop dark variant demonstrates strong execution of the xln wallet's core design principles, particularly in hierarchy, data legibility, and trust cues. The visceral value concept is well-implemented but needs more consistent application across all screens. The premium dark aesthetic is successfully achieved with minimal visual noise and excellent contrast.

- Consistently apply visceral value bars across all screens, especially in modals and list views
- Increase text size and contrast for scale indicators and capacity information
- Remove redundant information and streamline tooltips
- Enhance trust cues in payment and receive flows
- Standardize helper text sizes across the application

### zai-coding-cn/glm-4.6v · mobile-dark · 885

The mobile-dark variant demonstrates strong execution of the xln wallet's core value propositions with excellent visceral value visualization and trust-building elements. The design successfully implements the one-scale bar principle and provides clear provable payment confirmations. However, there are opportunities to improve typography hierarchy and reduce visual noise in several screens.

- Increase font size and emphasis of critical capability information (payment limits, fees)
- Improve visual hierarchy in activity lists with transaction type differentiation
- Enhance scale slider UX with clear value feedback in settings
- Increase QR code size for better scanning in receive flow
- Refine typography consistency across all screens for better readability

### zai-coding-cn/glm-4.6v · mobile-light · 810

The mobile-light wallet demonstrates strong foundation with excellent provability cues and visceral value bars, but suffers from inconsistent hierarchy, typography sizing, and some layout issues. ### openrouter/x-ai/grok-latest · desktop-light · 672

Light desktop is a calm two-column shell with real trust copy (frames, proofs, runtime verification) but the one-scale bar is only convincing on Account and Settings; Home, Activity, Receipt, Receive, and Swap break comparability. Light theme also introduces a black All chip, grey theme toggle, and hairline-zero bars that read as chrome rather than money.

- Enforce 1px=$50 on every bar (Home total, USDC row, Hub One, Pay Before/After, Receive amount, Swap pay, Activity amounts) and fade at card edge — delete any bar that is a full-width decoration at $0.
- Home: remove the On-chain/Reserve/Accounts dollar legend and the Instant send/receive duplicate; let the total and the account card each speak once.
- Activity + Receipt: represent −25.00 / +10,000.00 on the same scale; auto-open the latest receipt instead of the empty Select a movement card.
- One primary fill: indigo #6E7CFF for Pay/Copy/selected filter; stop using black All and washed lavender Swap-as-enabled.
- Pay/Swap/Receive: one amount format (tabular 25.00 USDC), one share/CTA, and don’t repeat Hub One bars in both columns.

### openrouter/google/gemini-flash-latest · mobile-dark · 835

xln wallet has an exceptionally rigorous fintech foundation, pairing uncompromising cryptographic provability with an inventive absolute-scale data visualization model. To reach top-tier polish on mobile, it must eliminate flow navigation conflicts like persistent tab bars inside subflows, tighten nested card sprawl, and treat tiny bar fractions with graceful minimums.

- Hide the bottom navigation tab bar in active transaction and flow sheets (Pay, Receive, Swap) to eliminate conflicting navigation hierarchies and reclaim thumb-zone canvas.
- Flatten nested card containers on mobile screens into edge-to-edge list groups separated by clean 1px hairline borders, eliminating wasted horizontal padding.
- Implement a minimum visual threshold (e.g. 3px pill or indicator pip) for sub-pixel scale values on the one-scale bar so small payments do not look like rendering glitches.
- Rebalance primary action aesthetics on Home and Receive: standardize the Pay/Receive/Swap action trio styling and tone down the stark white QR container.
- Add right-edge gradient fade masks to horizontal scrollable surfaces (Activity filter pills, Scale presets) to prevent awkward word truncation and clearly indicate overflow.

### openrouter/x-ai/grok-latest · desktop-dark · 664

Calm dark chrome, indigo Pay, mint settled, and the Hub One dual-bar (notch, amber owed, indigo room) are already a real fintech language; trust copy on Pay/Account/Receipt is ahead of the visuals. The product still fails its own visceral rule: almost every bar is fitted to the card, Home legends duplicate the total, Swap is an incomplete quote, and Activity wastes the desktop pane.

- Enforce 1px=$50 (Auto) on every bar: Home USDC row, Home/Pay/Account dual bars with edge fade, Pay Before/After $25 tick; stop stretching bars to 100% card width.
- Home desktop: delete the On-chain/Reserve/Accounts numeric legend and the Instant send/receive line that duplicates the Accounts card; shrink Pay/Receive/Swap so $11,500.00 wins.
- Swap: do not present an enabled Swap on 100 USDC → 0.00 WETH; quote or disable, and fill the empty right column with Before/After + rate.
- Activity: never show Select a movement…; default-select latest; disambiguate the twin Credit limit updated rows; align Time/Proof with receipt 03.
- Receive: darken the QR; drop 0.00-as-amount; one copy primary. Settings: one scale label; don’t twin Reveal recovery with Lock.

### openrouter/x-ai/grok-latest · mobile-dark · 662

Mobile dark has a strong money-total, mint settled states, and real frame/proof receipts, but the 1px=$50 law is taught in Settings and broken on Home, Pay, Receive, Swap, and Activity. Nested cards, repeated amounts, clipped chips/QR/copy, and a Swap with no quote keep it below a shipping fintech bar.

- Enforce one scale on every bar: Home token bar, Hub send/receive, Pay overlay for the $25, Receive request bar; hide '1 px = $50 · auto · 2 empty hidden' from Home.
- Delete duplicate money: Home legend vs bar vs Instant vs Accounts card; Pay amount vs This payment vs CTA; Account net vs limits table.
- One receipt component (PAID/SETTLED, frame, proof, verified) for pay sheet and activity detail; show a 25-unit mark so visceral value survives confirmation.
- Swap: no CTA without a receive amount and rate; draw the pay size at scale.
- Mobile chrome: hide tabs on Pay/Receive/Swap; don't clip QR, Entity ID, Activity filters, or Account explainer; collapse Copy invoice/link/xln:// to one primary.

### openrouter/google/gemini-flash-latest · mobile-light · 825

The mobile light theme establishes an exceptionally clean, authentic fintech foundation with rigorous mathematical backing and refreshing lack of crypto fluff. However, it suffers from anemic card contrast against the canvas, overly washed-out modal scrims, and inconsistent application of the flagship visceral bar across Swaps and Activity.

- Strengthen light-mode surface contrast by adding 1px subtle slate borders (rgba(15, 23, 42, 0.06)) to white cards and increasing modal sheet scrim opacity to rgba(15, 23, 42, 0.45) with backdrop blur.
- Bring the 'visceral value' 1px-scale bars into the Swap screen (both pay and receive inputs) and Activity row items so the core product signature is never absent.
- Fix CTA hierarchy on Swap ('Swap' button is washed out) and Receipt modals ('Done' button is low-contrast gray instead of high-emphasis slate/indigo).
- Clean up duplicate and uninformative activity entries by consolidating consecutive credit-line updates into single explicit delta states.
- Relocate the bar color legend inside the bilateral account card directly adjacent to the bar itself, rather than floating detached at the top of the screen.

### openrouter/x-ai/grok-latest · mobile-light · 633

Light mobile is a competent Cash App-adjacent shell with real proof cues (frame, runtime verify) but it is not yet a premium one-scale wallet: bars refit to cards, receipts have no bars, Swap is an unsafe empty state, and chrome (chips, legends, tab bar on modals, black All/Auto pills) keeps shouting. Trust is ahead of craft; visceral value and light-theme restraint are the gap to 800.

- Enforce one 1px=$N scale on Home total, token row, Hub One, Pay, Account, and a 25px tick on receipts; never independently fit bars to card width.
- Delete repeating legends/chips (On-chain/Reserve/Accounts text, hub chip, Instant line vs account captions, scale debug on Home).
- Hide the tab bar on Pay/Receive/Swap/receipt sheets and stop clipping QR, Entity ID, Activity Accou, and Settings Runtime.
- Block Swap until receive > 0; unify Pay success and Activity receipt into one component with copyable canonical proof.
- Rebind light theme: no black All/Auto pills, no grey Done-as-disabled, seed reveal demoted, Pay primary = indigo #6E7CFF not saturated blue tiles.
