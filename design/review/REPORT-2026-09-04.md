# Wallet design review — 2026-09-04

Scope: the React wallet in `ui/` (Home, Pay, Receipt, Receive, Swap, Account,
Activity, Activity detail, Settings) in four variants: desktop dark, desktop
light, mobile dark, mobile light. Scored 0–1000 on ten parameters
(`rubric.md`) by three vision models through the pi CLI and by me from the
same screenshots. Three fix passes were made during the day; every pass was
re-shot and re-scored.

## What changed today, by pass

**Pass 1 (r1 → r2)** — Activity rows collapsed to zero width on phones (an
inline grid override beat the media query); desktop-only asides leaked onto
phones (specificity); Home header lost "frame N"; token rows lost the
jurisdiction chip; Account: legend once, empty lanes collapsed, zero collateral
not green, ids shortened, "Ledger detail".

**Pass 2 (r2 → r3)** — Auto bar scale: one 1-2-5 step fits the largest
balance into the hero track (phone-aware), pinned scale kept, segments never
under 2 px. Toasts end on navigation and when the committed receipt appears.
One route diagram per viewport; hop fee shows its share of the total. Receipt
and Activity name the same finalizing frame and clock time. Receive, Settings
and Account detail use the desktop width; Settings previews the scale live.
Account settings out of the money column in Activity.

**Pass 3 (r3 → r4)** — Activity opens on the latest movement (no empty
pane); paired credit-line entries fold into one "both ways" row; Pay,
Receive and Swap hide the phone tab bar; receipt Done is primary; light theme
cards lifted and secondary ink darkened.

**Pass 4 (r4 → r5)** — Light theme: chips and the segmented control use the
accent tint instead of black, stronger sheet scrim. Payment rows in Activity
and Recent draw the amount at the one scale (the receipt does not: a lone
sliver under one number compares with nothing). Entity ids, proofs and the
runtime id copy on tap. Light now scores level with dark on Pay, Account and
Settings; Home and Receive still trail by 25–30.

## Backlog, ordered by expected score gain

1. **Swap needs a price.** Suggested rate from the hub (last fill or book mid), a rate line, and no enabled CTA without a receive amount. All three reviewers, every run. Needs a book/price read from the runtime; the sandbox hub has no book yet.
2. **Bars in Receipt and Activity rows.** The one-scale principle stops at Home/Pay/Account. A 4 px at-scale bar under the receipt amount and inside rows would carry it through. Grok and Gemini, every run.
3. **Home duplicates.** Legend under the hero, the "Instant" line and the Accounts card say the same numbers three ways. Try legend on hover/tap only; keep "Instant" as the one capacity line. Grok r1–r3.
4. **Receive.** QR smaller on desktop (200 px), one primary copy action, request bar only when an amount is set.
5. **Light theme.** Still −30 to −60 versus dark on `premium`/`color`. Next: black "All" chip → indigo, theme toggle contrast, hairline-zero bars removed.
6. **Mobile chrome.** Flatten nested cards into edge-to-edge groups on phones; fade masks on horizontal chip rows.
7. **Copy affordances** on every truncated id/hash (one-click copy, hover full value).
8. **Vocabulary.** "Frames signed", "committed entries": crypto-native reads fine, mainstream users do not. Decide the audience before renaming.

Not done on purpose: the Home legend/"Instant" line stays (the owner asked for
the three places folded and visible), Swap pricing needs a book/price read the
sandbox does not have, flattening mobile cards is a taste call I am not 90 %
sure of.

Two items are blocked on core, not design: the twin credit-line rows cannot be
labelled yours/theirs, and payment recipients come from a local binding
(`docs/audit/2026-09-04-wallet-ui-core-findings.md`, items 1, 2 and 5).

## How to run the loop

```bash
cd ui && bun run dev                              # :5183, leave running
bun ui/tools/design-shots.ts                      # 4 variants × 9 screens → design/screenshots/ui/
bun ui/tools/design-review.ts --run <name>        # GLM-4.6V + Gemini Flash + Grok → design/review/<name>/summary.md
```

Fix, re-shoot, re-score. `--models`, `--variants`, `--resummarize` are
documented in `design/review/README.md`. One full run costs about 12 model
calls (≈ 1–2 min each) and is entirely on the cheap plans.
