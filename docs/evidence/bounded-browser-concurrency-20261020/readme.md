# Bounded browser concurrency

The seven-stack browser cohort repeatedly exceeded the unchanged 55-second routed Move budget. Independent Alice/Bob observations now overlap while retaining every read, each owner’s internal order, all exact balances and receipts, and both errors before teardown. This reduced observation time in one traced sample but did not close the loaded cohort failure. Existing phase timing records the first slow boundary.

The same seven tests, source and arguments were then compared at seven, four and two active stacks. Seven failed the Move deadline; four failed Direct Move reload’s original five-second Home expectation before the routed case completed. Two passed all seven with strict browser health and no skips. The direct reload also passed alone, with Home reached 4.20 seconds after Unlock. These observations justify bounding normal release scheduling; they do not identify every host resource contributing to latency.

Normal functional, resilience, combined, full and release scripts now request two stacks. Test selection, financial assertions, inner deadlines, cold-reset serialization and the single stand lock are unchanged. Explicit maximum-parallel experiments retain their separate settings; their higher concurrency is not certified.

Discovery and reset-limiter regressions passed 12 tests with 33 assertions. [proof.json](proof.json) retains commands, source bindings and every failed experiment. The seven-case cohort does not certify all 158 browsers or the final immutable-SHA financial/release gates.
