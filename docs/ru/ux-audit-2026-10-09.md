# Аудит двух кошельков: найденные проблемы и исправления

Проверены React (`localhost:5183`) и эталонный Svelte (`https://localhost:8080/app`) на одноразовых кошельках локального тестнета. В отчёте 23 пункта: 7 супер важных, 11 средних и 5 небольших. Часть исправлена, оставшиеся ограничения отмечены явно. Это результаты реальных действий в браузере и отдельных регрессионных тестов. Сборка сама по себе не доказывает завершение финансового сценария.

Исходный коммит аудита: `4d8ee444c67c08df65922c04691456299b3358c0`; во время общей работы HEAD перешёл на `96d361e0487449ab941966d4bcd661537e96d3ab`. Правки этого аудита остаются в рабочем дереве; этот чат не делал коммит или push. [Исходные свидетельства](../evidence/ux-audit-2026-10-09/) сохранены вместе с первым отчётом.

## Принятые решения владельца

1. Главная цифра — общий баланс; доступное для платежа показывается отдельно. Неиспользованный кредит не является балансом.
2. Функции остаются видимыми. Подсказки и раскрывающиеся пояснения постепенно обучают новичка.
3. После отправки свопа остаётся форма; открытый ордер отображается ниже, пока не исполнится или не будет отменён.
4. Резервное копирование и защита предлагаются сразу в свёрнутом разделе. Настройка, сохранённая копия и работающая защита — разные состояния.
5. Ошибка содержит понятное объяснение и полный технический текст сразу. Ошибки можно закрыть вручную; они не исчезают через несколько секунд.

## Что действительно было пройдено

В исходном проходе: создание brainvault, тестовое пополнение, платежи между кошельками и получение, обычный своп и отмена, перенос средств, изменение лимитов, подключение хабов, начало диспьюта, просмотр lending, блокировка и вход, история и сброс. По каждой из восьми основных категорий были действия в обоих интерфейсах: 16/16 категорий затронуты, что **не означает 16 успешных завершений**.

Дополнительно после исправлений:

- Invoice React на 1 USDC с заметкой распознан Svelte; React получил платёж и показал Settled с заметкой и hashlock.
- Межсетевой обмен двух кошельков завершён: React 100 → 90 USDC в Testnet и 0 → 0,004 WETH в Tron; Svelte отдал 0,004 WETH в Tron и получил 10 USDC в Testnet. Ордера исчезли из открытых после исполнения. История React пока показывает несколько фаз вместо одной итоговой записи — M9 остаётся открытым.
- Svelte сохранил обе сети и ненулевые балансы после lock/reload/unlock. В React по умолчанию показана USD-оценка всех активов выбранной сущности; точные единицы токена можно выбрать отдельно.
- Локальный tower сохранил зашифрованную копию. В чистом origin `http://[::1]:5183` восстановлены обе сущности, 90 USDC и 0,004 WETH. Relay этого origin отклоняет соединение; продолжение платежей из него не проверено. В обычном `localhost` повторный вход работает.
- Tower принял две заявки защиты, но сообщил, что автоматический ответ отключён. UI явно показывает это; фактическая автоматическая защита не подтверждена.
- React на ширине 390 CSS-пикселей: главная и оплата без горизонтального переполнения. В Svelte на той же ширине обнаружены и исправлены скрытый баланс и меню операций.

Целевые тесты: 156 прошли, 0 упали, 771 проверка утверждений в 24 файлах. Дополнительная проверка платёжной проекции: 11/11 тестов, 143 утверждения (частично пересекается с основным набором). `bun run check` после серверных исправлений прошёл: 39/39 проверок исходников, обе верхнеуровневые группы, Svelte без ошибок и предупреждений. Frozen core не изменён. Финальный прогон после мобильной вёрстки также прошёл; `git diff --check` прошёл.

Два конкурирующих запуска останавливали dev во время браузерной проверки. Владелец явно отдал приоритет аудиту: последний прогон остановлен вместе с дочерними процессами, соседний чат подтвердил, что не будет занимать стенд. Во время изолированных E2E dev остановлен, чтобы соблюсти ограничение одного стенда. Неинформативные ошибки запуска BrainVault worker заменены объяснением и полным кодом.

Остаются без доказанного успешного завершения: единый браузерный сценарий назначения защиты с выключением кошелька и multisigner ownership. Автоматический ответ tower отдельно доказан RPC-тестом ниже. Для обычной browser entity Svelte прямо сообщает, что выпуск долей требует номерного on-chain entity ID. Проверки mainnet не проводились.

Полный цикл займа, погашения и финализации диспьюта теперь проверен в обоих UI; следующий приоритет — автоматическая защита. Эти результаты не являются заявлением, что всё доведено до идеала.

## Повторная проверка lending и бэкапов

Владелец поручил самостоятельно выбрать понятное представление lending. Реализовано: 100 USDC общего баланса = 95 на аккаунте + 5 во вкладе. Выплата возвращает 5 в доступное, не увеличивая общую сумму. Одинаковый результат проверен реальными кликами в React и Svelte на новых кошельках `ux-oct09-recovery-react` и `ux-oct09-recovery-svelte`.

При длительном прогоне обнаружена дополнительная причина отказа бэкапов: React использовал экспорт записи с историей вместо готового снимка текущего состояния, а HTTP-прокси ограничивал тело 1 МиБ при квоте башни 4 МиБ. Исправлены обе причины:

- Автобэкап использует существующий `encryptTip`: подписанный снимок и журнал его текущего кадра под committed-read lease. История старых операций остаётся на исходном устройстве; восстановление текущих денег не требует повторной отправки всего архива.
- Транспорт прокси допускает до 8 МиБ; остальные API-маршруты сохраняют ограничение 1 МиБ, включая потоковые запросы без Content-Length. Health сообщает фактический предел загрузки, клиент проверяет полное подписанное тело отдельно от квоты хранения.
- Повторная ошибка бэкапа обновляет одно уведомление; повторная попытка через 60 секунд вместо бесконечного накопления сообщений каждые 5 секунд.
- Настоящий зашифрованный бэкап больше 1 МиБ прошёл загрузку, запись, чтение через production proxy и расшифровку: 7 утверждений. Из браузера башня сохранила свежий снимок кадра 230, UI показывает 47 КБ. В отдельном origin восстановлен общий баланс 100, доступно 95, вклад 5. Платежи из IPv6-origin по-прежнему не проверены из-за relay allowlist.

Свидетельства: [React — вклад в общем балансе](../evidence/ux-audit-2026-10-09/react-lending-total-fixed.png), [Svelte — вклад](../evidence/ux-audit-2026-10-09/svelte-lending-total-fixed.png), [свежий бэкап](../evidence/ux-audit-2026-10-09/react-backup-fixed.png), [восстановление](../evidence/ux-audit-2026-10-09/react-lending-restored.png).

Обновлённый целевой набор: **191 тест прошёл, 0 упало, 884 утверждения в 28 файлах**. Финальный `bun run check` прошёл: 39/39 проверок исходников, обе верхнеуровневые группы. Svelte: 0 ошибок и предупреждений. `git diff --check` прошёл. Во время одного предыдущего общего прогона посторонний тест остановки группы процессов упал с `kill: EPERM`; отдельно 18/18 его тестов и последующий общий прогон прошли. ## Исправление основного долга и отдельные быстрые/E2E-проверки

Выявленная финансовая ошибка закреплена падающим тестом: лимит 20 000 ошибочно становился 22 500 при выдаче 2 500. Применено уже принятое владельцем решение: перевести основной долг один раз. Старый формат кредитной выдачи удалён из TS/Rust, wire и восстановления. Старые данные этого lending-протокола явно отвергаются; автоматической переинтерпретации нет.

- `bun run test:lending:fast`: **44/44 теста, 246 утверждений, 0,54 с**. Сценарии проверяют сохранение денег, проценты, повторы, недопустимого плательщика, просрочку, неприкосновенность лимитов и старый wire.
- `bun run test:lending:e2e`: **3/3 E2E, 41,6 с**, без пропусков и моков. React: подготовка входящего лимита перед выводом (10,0 с); отдельные вкладчик и заёмщик, выдача, трата полученных денег, погашение и вывод с процентами (17,0 с). Svelte: новый Brain Vault, вклад, выдача, погашение и возврат вклада через UI (13,8 с).
- Rust: **5/5 Account-проверок и 5/5 Entity/планировщика**, совпадение с общим TS-вектором. Общий `bun run check` после изменений прошёл 39/39 проверок исходников; последняя группа исходников — 37,1 с. Это не доказательство live Rust lending во всех сетях.
- Сам E2E выявил отдельную ошибку: React обнулял отрицательную долларовую оценку займа. Теперь использует общий со Svelte расчёт. Пример в обоих интерфейсах: 100 своих + 2 займа − 2,02 обязательства = **99,98 общего баланса**, 102 на аккаунте до погашения.

Ограничения lending остаются явными: подбор заявок автоматический, ручной андеррайтинг ещё не реализован; вклад — обязательство хаба, пока не отдельное исполнимое в J требование; позднее погашение defaulted-займа не покрыто этим исправлением. Эти ограничения не скрыты под успешными тестами обычного сценария.

Свидетельства: [быстрые тесты](../evidence/ux-audit-2026-10-09/lending-fast.log), [три E2E](../evidence/ux-audit-2026-10-09/lending-e2e-all.log), [финальная общая проверка](../evidence/ux-audit-2026-10-09/lending-principal-final-check.log), [Svelte после полного цикла](../evidence/ux-audit-2026-10-09/svelte-lending-e2e-settled.png).

## Автоматическая защита tower на реальном контракте

`bun run test:watchtower:rpc`: **2/2 теста, 4,49 с**. Первый тест больше не вызывает обработчик защиты вручную и не подставляет фабрики RPC/контракта. Настоящий daemon получает подписанное назначение через HTTP, опрашивает разрешённый RPC своим таймером, пропускает раннее окно, сам публикует контрдоказательство и сам финализирует после срока. Проверены ровно две отправки, отсутствие ошибок, nonce, нулевой залог и возврат 800/200 единиц двум сторонам. Второй тест доказывает, что старое назначение tower не заменяет более новое пользовательское контрдоказательство.

Это закрывает проверку автоматического сервиса на локальном EVM-контракте. Назначение из UI, выключение браузера и ответ сервиса в одном E2E, а также native TVM остаются отдельными проверками. [Лог автоматической защиты](../evidence/ux-audit-2026-10-09/watchtower-automatic-rpc.log).

## 10 октября: юрисдикции и полный учебный маршрут

В обоих интерфейсах появился постоянный блок юрисдикции: название, chain ID, цвет фона и раскрываемые адреса Depository/Entity Provider. Цвета различают Ethereum, TRON, XLNC и локальную тестовую сеть; неизвестная сеть сохраняет собственное название. Переключение сущности обновляет контекст сети на всех экранах.

Общий курс содержит 14 глав: тестовые деньги, платёж, своп/ордера, история, юрисдикции, получение, хабы, лимиты, перемещение/расчёт, lending, восстановление/защита, компания, акции, диспьют. Он находится в потоке страницы, не перекрывает форму, сохраняет главу и позволяет вернуться к любой теме. Переход главы не подписывает операцию и не считается доказательством её исполнения.

Проверки: **7/7 браузерных сценариев**, **5/5 быстрых регрессий**, `bun run check` — 39/39 проверок исходников и обе верхнеуровневые группы. E2E подтверждают реальные funding → платёж 25 USDC → получение WETH → историю, регистрацию компании, обе категории акций в резерве и открытие нового кошелька после выпуска. Отдельно проверены главы обоих интерфейсов, смена юрисдикции, пауза без потери введённой суммы, мобильная ширина и отсутствие повторного faucet. Проход остальных глав проверяет навигацию и доступность объяснений; он не является новым доказательством исполнения всех описанных финансовых операций. Полный диспьют и многоподписная компания в этом прогоне не исполнялись.

Найден и исправлен блокер: импорт юрисдикции запрещал разные ERC-1155 токены одного контракта. После выпуска акций это останавливало новые кошельки. Проверка теперь использует каноническую идентичность Depository: `(tokenType, contractAddress, externalTokenId)`. Повторная ссылка под другим внутренним ID по-прежнему отвергается; разные классы акций разрешены, точная повторная доставка идемпотентна.

Быстрый браузерный проход: из `ui` выполнить `bunx playwright test -c playwright.config.ts e2e-tutorial-features.spec.ts` (последний прогон 13,3 с). Финансовые сценарии запускаются отдельно: `e2e-tour.spec.ts` и `e2e-tutorial-company.spec.ts`. Svelte: `UI_E2E_BASE_URL=http://localhost:8081 bunx playwright test -c playwright.config.ts e2e-svelte-tutorial.spec.ts`. Все используют уже работающий единственный dev-стенд; параллельно второй стенд не запускать. Перед прогоном проверить `bun run stand:status` из корня.

## 10 октября: полный диспут и восстановление в обоих интерфейсах

Четыре отдельных браузерных E2E прошли на изолированных production-стендах, без моков и пропусков:

| Сценарий | Время теста | Проверенный результат |
| --- | --- | --- |
| React: диспут | 17,6 с | Раннее завершение запрещено; после подписанного срока 100 USDC возвращаются в резерв и выводятся владельцу |
| Svelte: диспут | 16,9 с | Тот же возврат и вывод; UI показывает 100 USDC во внешнем кошельке и нулевой резерв |
| React: восстановление | 21,5 с | Новый браузер, совпадение канонического корня, отказ от перезаписи существующего кошелька, платёж после восстановления |

Время не включает запуск стенда. В диспутных тестах ускоряется время только отдельной локальной цепочки и браузера; контракты, подписи, транзакции и квитанции настоящие. Ожидание суток в реальном времени, native TVM, злонамеренные контрдоказательства и спасение tower при выключенном браузере этими четырьмя тестами не доказаны.

Исправления Svelte: непрерывные обновления больше не откладывают backup навечно; backup использует проверенный снимок committed-состояния вместо недопустимого хвоста WAL; завершённый onboarding восстанавливается вместе с кошельком; список recovery-сервисов сразу соответствует выбранному режиму. React больше не называет завершённый диспут продолжающимся. Подписи о возврате в резерв остаются корректны и после вывода средств.

Быстрые проверки: **76/76**, 425 утверждений. Повторить: `bun run test:dispute:fast`, `bun run test:recovery:fast`; полные пути: `bun run test:dispute:e2e`, `bun run test:recovery:e2e`. Исправлен формат аргументов stand-запускателя: 180 секунд действительно применяются вместо молчаливого завершения через 30 секунд.
