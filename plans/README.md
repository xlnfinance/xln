## Verdict

Split the frontend into independently built `site`, `docs`, `wallet`, and `ops` surfaces, but keep them in one repository, on one origin, and in one coordinated release. A React 19 + Vite 7 + TypeScript rewrite is feasible, but it is a large product migration rather than a mechanical framework swap: 151 Svelte files (79,946 LOC), 206 TypeScript files (38,295 LOC), 39 Svelte-aware unit tests, 47 Playwright specs, native shells, root-scoped PWA behavior, localStorage, IndexedDB, and runtime bridge state all cross the present boundary.

The rewrite should proceed only because the owner explicitly wants React. The audit found no evidence that React alone will improve performance or correctness. Estimated execution is 60–95 engineer-weeks, with the wallet/state portion carrying most of the risk.

## Target architecture

| Surface | Canonical paths | Build output | Ownership |
|---|---|---|---|
| Site | `/`, `/install`, `/rcpan`, `/releases`, `/reviews`, `/unicast` | `frontend/build/site` | Public acquisition and release information |
| Docs | `/docs`, `/docs-catalog/**`, `llms*` | `frontend/build/docs` | Generated documentation catalog and reader |
| Wallet | `/app`, `/address/**`, `/testnet` | `frontend/build/wallet` | Vault, runtime bridge, payments, PWA, native shells |
| Ops | `/health`, `/qa`, `/runs`, `/scenarios`, `/ai/**`, `/embed` | `frontend/build/ops` | Developer/operator tooling and runtime-free scenario embeds |

`/rpc`, `/rpc2`, and `/resetdb` remain runtime/edge endpoints, not React pages. `/admin` remains the existing edge redirect to `/health`; `/radapter` remains the query-rejecting edge redirect to `/app` unless the owner explicitly retires either redirect. All surfaces continue to ship at `xln.finance` path prefixes. Moving the wallet to another origin is specifically rejected because origin-bound vault metadata, runtime journals, PWA scope, and push wake behavior would require an authenticated data migration.

Use one `frontend/package.json` and lockfile initially. Put entry applications under `frontend/apps/{site,docs,wallet,ops}` and shared code under `frontend/packages/{ui,client-core,runtime-client,build-contracts}`. Vite multi-page inputs produce separate artifacts; the default development command must still expose the complete same-origin application on `localhost:8080`.

## Audit findings that shape the plan

- `frontend/src/routes/+layout.svelte` and `frontend/src/app.html` currently make analytics, top navigation, native initialization, redirect policy, and route mode global. Those responsibilities must move to explicit surface entry points.
- Native mobile, Electron, and extension builders consume the whole `frontend/build`; they must consume a release manifest rather than discover files implicitly.
- `frontend/copy-static-files.js` combines docs generation with contracts, workers, scenarios, and release assets. The docs producer must become deterministic and independently callable.
- The public top bar currently exposes `DeltaVisualizer.svelte`, whose local delta calculation diverges from canonical `runtime/account/utils.ts` historical-credit behavior. That duplicate formula must be removed before migration, not translated to React.
- The current server deployment deletes `frontend/build` before extraction and checks only `index.html`. Multiple artifacts make that outage window and partial-release risk unacceptable; Plan 002 is a prerequisite to cutover.

## Decisions rejected or deferred

- Rejected: `app.xln.finance`. It breaks origin-bound state unless a separately approved migration protocol is designed.
- Rejected: independent surface versions or release trains. One tagged commit, version, artifact manifest, and activation remains the release unit.
- Rejected: adding Next.js, SSR, or a router migration to this rewrite. Vite multi-page entries preserve the present static URL contract with less simultaneous change.
- Rejected: ad-hoc React `useEffect` mirrors of Svelte stores. Framework-neutral external stores expose `subscribe`/`getSnapshot`; React consumes them with `useSyncExternalStore`.
- Deferred: prerendering/SSR and cross-origin decomposition until after parity and production stabilization.
