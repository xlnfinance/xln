# cross-j: og cross-jurisdiction extension, HTLC envelope and Account outputs vs pure/xln.ts

Tests: `pure/diff/cross-j/cross-j.test.ts`. Run from `pure/` with `bun test diff/cross-j/cross-j.test.ts`: 15 pass, 0 fail.

Every test is `MATCH:` and runs against live og (`core/`, HEAD 566c850). There are three kinds of test:

- **Pure-function tests.** They call the og export and the rewrite function on the same random input. A throw from og counts as a reject. When both sides accept, the values must match as `stableJson`, a port of og `safeStringify`.
- **Account-level lockstep tests.** They reuse the `ogHarness` pattern from `account-tx.test.ts`. A persistent og replica is seeded from the rewrite's committed view and driven through the real transition overlay. Both sides must agree on accept or reject. Every accepted tx must give the same `accountStateRoot`.
- **Output tests.** They go through og `applyAccountTxMutation`, so the og outcome and `candidateEffects` are compared too.

All randomness comes from a seeded mulberry32.
