# hashes-codecs: og vs pure/xln.ts

Tests: `pure/diff/account/hashes.test.ts`. Run it from `pure/` with `bun test diff/account/hashes.test.ts`. Result after the fixes: 48 pass, seeded mulberry32 PRNG (`0xC0FFEE`). Former DIVERGES tests for fixed findings are now MATCH tests; the remaining DIVERGES tests (H5, H6) belong to other areas. The og side is always og's own function, or the typechain ABI generated from the `.sol` files. ethers `solidityPacked` stands in for og only where og has no exported function; that happens once, for `Account.sol _encodeDisputeHash`.

## Coverage: og behaviours confirmed as MATCH

- **RLP canonical value:** `encodeCanonicalValue` equals og `encodeAccountStateValue` and `encodeAccountStateValueOracle`. Checked on 500 random nested values (bigint ±2^255, uint256 max, -0, maps with many mixed keys, sets, undefined-valued keys, unicode), plus edge scalars. Both refuse lone surrogates.
- **Flat integrity digest:** `flatDigest` equals `computeCanonicalMerkleRoot(ns, …, 'integrity')` on 200 random section lists.
- **Radix-16 Patricia map root:** `mapRoot` equals og `PersistentAccountStateMap.rootHash`. Checked on 400 random maps with 0 to 40 keys, numeric and string keys, `MAX_SAFE_INTEGER`, and mixed non-colliding keys. Both refuse prefix collisions, nested collections, and leaves over 10,000 bytes.
- **Account state commitment:** `accountStateCommitment` equals og `computeAccountStateRoot` on 200 random states without a settlement workspace. These include mixed-case ids, seeds and roots, zero and checksummed depositories, and random j-claim accumulators. Both refuse a bad EIP-55 mixed-case depository.
- **Account frame hash:** `accountFrameHash` equals og `computeFrameHash` on 300 random frames, including stripping of settle_transition Hanko witnesses. Both refuse an unsafe `rebalance_policy.policyVersion`.
- **Event topics:** `HankoBatchProcessed`, `ReserveUpdated`, `DisputeStarted` and `DisputeFinalized` equal the Depository ABI. `readJEvents` decodes contract-encoded logs of those four kinds correctly (50 random each, including uint256 max and mixed case).
- **Batch encoding and batch hash:** `encodeBatch` equals og `encodeJBatch` for 200 batches without settlements or disputes: R2R, R2C, C2R, external tokens, reveals, hash-ladder with `bytes32[4]`, and `uint8`/`uint16` fields. The empty batch also matches. `encodeBatchHash` equals og `computeBatchHankoHash` (100 random).
- **Dispute digests:** `encodeDisputeProofHash` plus `encodeAccountKey` equals og `createDisputeProofHashWithNonce` (200 random, mixed case, max nonce). `encodeDisputeHash` equals the `Account.sol _encodeDisputeHash` / `_argumentCommitment` packing (100 random).
- **Hanko:** Several functions match their og counterparts:
  - `encodeLazyEntityId` equals `lazySingleSignerEntityId`.
  - `encodeHanko65` equals `recoverShortHankoEntityId` for v in {0, 1, 27, 28}; both reject high-s.
  - `encodeHankoEnvelope` and `packSignatures` produce the same bytes as og for canonical input.
  - `verifyAccountHanko` accept/reject and target equal og `verifyCanonicalHanko` on 300 random board Hankos: random thresholds and weights, placeholders, duplicate indexes, weight 0 or over 65535, wrong target, registered-board authority, unused placeholders. The nested-claim and unused-claim cases also agree.
- **`EMPTY_J_ROOT`** equals og `EMPTY_ACCOUNT_J_CLAIM_ROOT`.
- **Entity frame hash:** `entityFrameHash` equals og `createEntityFrameHashFromStateRoot` on 200 random frames. These cover plain txs, the `accountInput` commitment digest, events, and hex projection of strings of 34+ lowercase hex characters versus shorter, odd-length or uppercase ones.
- **Entity account leaf:** matches og `computeEntityAccountValueHash` through the full root, on 50 random multi-account states restricted to the fields the rewrite models.
